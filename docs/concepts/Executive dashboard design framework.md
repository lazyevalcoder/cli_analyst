# Executive dashboard design framework
## Purpose

A dashboard should not start with metrics. It should start with the **business outcome** and work backwards to answer the decisions leaders need to make.

The flow:

**Business Outcome → Executive Questions → KPIs → Supporting Metrics → Insights → Actions**

---

# 1. Business Outcome

## Definition
The strategic business result the organization is trying to achieve.

Answers:
> "What are we trying to accomplish?"

Examples:
- Grow mid-market revenue
- Improve profitability
- Increase market share
- Improve customer retention
- Increase sales efficiency
- Build predictable revenue growth

---

# 2. Executive Questions

## Definition
The key decisions leaders need to make to achieve the business outcome.

Answers:
> "What do we need to understand?"

Good executive questions:
- Are we on track to achieve the outcome?
- What is driving or limiting performance?
- Where are we losing opportunities?
- What risks require intervention?
- Where should we invest more resources?
- What decisions need to be made?

Avoid:
- Metric-focused questions
- Operational reporting questions

Example:

Weak:
"How much pipeline do we have?"

Strong:
"Is our pipeline generation engine sufficient to support future growth?"

---

# 3. KPIs

## Definition
The 1-3 most important indicators that directly answer the executive question.

Answers:
> "How do we know if we are winning or losing?"

Characteristics:
- Few in number
- Outcome-oriented
- Executive-level
- Directly tied to decisions

Examples:
- Revenue attainment
- Pipeline coverage
- Forecast accuracy
- Customer retention rate
- Gross margin

---

# 4. Supporting Metrics

## Definition
Additional metrics that explain KPI movement and help diagnose problems.

Answers:
> "Why is the KPI changing?"

Characteristics:
- Diagnostic
- Provides context
- Helps identify root causes

Examples:
- Win rate
- Conversion rates
- Sales cycle length
- Customer acquisition cost
- Deal size
- Segment performance
- Channel performance

---

# 5. Insights

## Definition
The interpretation of data that explains what is happening and why.

A metric is a fact.
An insight is the meaning behind the fact.

Example:

Metric:
"Win rate declined from 35% to 25%."

Insight:
"Pipeline quality has declined due to weaker qualification in new customer acquisition."

Good insights:
- Explain cause
- Highlight risks/opportunities
- Identify patterns
- Enable decisions

---

# 6. Actions

## Definition
The decisions or interventions required based on insights.

Answers:
> "What should we do next?"

Examples:
- Change GTM investment allocation
- Adjust territory strategy
- Improve qualification process
- Increase investment in high-performing channels
- Address customer retention risks

---

# Design Principles

## 1. Start with decisions, not data
Executives do not need more metrics; they need better decisions.

## 2. Every metric must have a purpose
A metric exists because it answers a business question.

## 3. Separate KPIs from diagnostics
KPIs tell you what is happening.
Supporting metrics explain why.

## 4. Insights are the bridge
The value of analytics comes from converting data into understanding.

## 5. Actions complete the loop
A dashboard is successful when it changes decisions and behavior.

---

# Example Structure

## Business Outcome
Increase mid-market revenue

### Executive Question
Are we acquiring enough high-value mid-market customers?

### KPIs
- Mid-market revenue growth
- Pipeline coverage
- Win rate

### Supporting Metrics
- Pipeline by source
- Average deal size
- Sales cycle
- Segment conversion
- Customer acquisition cost

### Insights
Pipeline growth is strong, but conversion is declining due to lower-quality opportunities.

### Actions
Improve ICP targeting and reallocate demand generation investment.

---

# Core Principle

A great executive dashboard answers:

1. What is happening?
2. Why is it happening?
3. Where should we focus?
4. What decision should we make?

The dashboard is not a reporting tool.
It is a decision-support system.
