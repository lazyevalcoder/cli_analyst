# Pipeline Operating System

> **Principle**
>
> This is not a dashboard. It is an operating system for running the sales pipeline.
>
> Every component answers:
>
> **What changed? → Why? → What should we do? → How do we investigate?**
>
> The operating review focuses on execution. Analytical lenses are used for root-cause analysis and long-term improvements.

---

# Operating Flow

```text
Build Pipeline
      │
      ▼
Advance Pipeline
      │
      ▼
Convert Pipeline
      │
      ▼
Revenue

            ▲
            │
     Optimize the Sales Engine
            │
            └────────────── Feedback Loop
```

The first three outcomes are operational and should be reviewed frequently (daily/weekly).

The optimization outcome is strategic and should be reviewed periodically (monthly/quarterly).

# Domain: Pipeline Analytics

## Outcome 1 — Build Pipeline

**Objective**

Create enough qualified pipeline to sustain future revenue.

### Executive Question

**Are we creating enough pipeline?**

**Primary KPI (Δ)**
- Pipeline Created (% change)

**Context**
- Current Pipeline Value

**Drivers**

- Δ Average Deal Size

- Δ Pipeline by Product

    ▼

# Design Principles

1. Organize around business outcomes, not reports.
2. Every outcome should support one executive objective.
3. Every question should lead to exactly one business decision.
4. KPIs should emphasize **change (Δ)** rather than absolute values.
5. Supporting metrics should explain *why* the KPI changed—they are drivers, not miscellaneous metrics.
6. Operational reviews answer today's execution questions.
7. Analytical lenses exist for deeper investigation and long-term improvement.
8. The operating system should follow the natural business lifecycle, not the underlying data model.
9. Each outcome feeds the next, creating a continuous operating loop.
10. Strategic optimization feeds back into operational execution, closing the loop.
