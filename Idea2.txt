# AI Data Analyst MVP

Build an MVP of a CLI-first AI Data Analyst.

The goal is to create a small but well-architected system that can ingest datasets, build knowledge graphs, and answer questions about the data. Prioritize clean architecture, extensibility, and simplicity over features.

## Scope

The project has two knowledge graphs.

### 1. Structural Knowledge Graph (SKG)

Represents the factual structure of the dataset.

Nodes may include:

* Dataset
* Table
* Column
* Entity
* Metric
* Dimension

Relationships include:

* HAS_TABLE
* HAS_COLUMN
* FOREIGN_KEY
* REFERENCES
* ATTRIBUTE_OF
* MEASURES

This graph is deterministic and can always be rebuilt from the source data.

---

### 2. Diagnostic Knowledge Graph (DKG)

Represents analytical knowledge generated by the system.

Nodes may include:

* Metric
* KPI
* Anomaly
* Hypothesis
* Insight

Relationships include:

* CAUSES
* DEPENDS_ON
* CORRELATES_WITH
* EXPLAINS

Every edge should support metadata such as confidence, evidence, timestamp, and source.

---

## MVP Features

### Project

```bash
analyst init sales-project
```

Creates

```
sales-project/
    analyst.yaml

    data/

    graphs/
        structural.skg
        diagnostic.dkg

    metadata/

    analyses/
```

---

### Load data

```bash
analyst load data/sales.csv
```

The system should

* detect schema
* infer data types
* identify entities
* profile columns
* save metadata

---

### Build Structural Graph

```bash
analyst build skg
```

Creates a structural knowledge graph from the dataset.

The graph should contain

* datasets
* tables
* columns
* metrics
* dimensions
* inferred relationships

---

### Ask questions

```bash
analyst ask
```

Examples

```
What metrics exist?

What dimensions exist?

How are customers related to orders?

Show the schema graph.

What joins are available?
```

Answers should be generated using the structural graph rather than directly scanning the dataset whenever possible.

---

### Diagnostic Analysis

```bash
analyst analyze
```

The system should

* detect simple anomalies
* compute metric changes
* generate hypotheses
* build or update the diagnostic graph

Example

```
Revenue ↓

↓

Orders ↓

↓

Conversion ↓
```

Store these relationships in the diagnostic graph with confidence scores.

---

### Explain

```bash
analyst explain revenue
```

Uses the diagnostic graph to explain why a metric changed.

---

## Storage

The project should be self-contained.

Use a project directory rather than a single database.

Store graphs as property graphs serialized to JSON for the MVP.

Example files

```
graphs/
    structural.skg
    diagnostic.dkg
```

These are JSON internally.

The storage format should be abstracted so it can later be replaced with SQLite, DuckDB, or another backend without changing the graph API.

---

## Design Goals

* CLI-first
* Modular architecture
* Clean separation between ingestion, graph building, reasoning, and storage
* Graphs are persistent
* Analyses are reproducible
* Future GUI should reuse the same core engine
* Easy to extend with new graph types and plugins

Keep the MVP small. Build only the core functionality needed to demonstrate the architecture. Avoid premature optimization and avoid features outside this scope.
